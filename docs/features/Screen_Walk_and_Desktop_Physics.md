# Screen Walk & Desktop Physics (화면 외출 및 데스크탑 상호작용 시스템)

> **상태**: 📋 상세 기획 및 설계 완료 (Stage 13 이후 구현 예정)
> **대상**: Noah 데스크탑 동반자 애플리케이션
> **기획 보강 일자**: 2026-06-07

---

## 1. 개요 및 비전

노아는 평소에는 자신의 3D "방(Room)" 공간 안에 confinement(감금)되어 생활하지만, 특정 감정 상태/자율 행동 의사결정에 의해 방 밖으로 걸어 나와 **사용자의 바탕 화면 공간 전체를 활보**할 수 있습니다. 

단순히 사각형 창 구석에 존재하던 노아가 가상 창의 경계를 파괴하고 실제 사용자의 동반자로서 데스크탑 세계에 존재하는 물리감을 선사합니다. 특히 사용자가 실제로 사용 중인 **OS 활성 윈도우들(인터넷 브라우저, 메모장, 코딩 편집기 등)의 구조와 경계를 인식하고, 그 상단 바 지붕 위에 걸터앉거나, 발로 딛고 걷거나, 미끄러지는 데스크탑 인터랙티브 피직스**를 제공합니다.

## 2. 윈도우 렌더링 및 입력 상태 변환 아키텍처

데스크탑 외출 시, 노아와 방의 상태는 고정된 `400x600` 단일 창 형태에서 **투명한 전체 화면 마우스 포인터 투과(Click-Through) 오버레이** 구조로 변환됩니다.

```
                  [방 안 모드 (Default)]                         [화면 외출 모드 (Walk Mode)]
       ┌──────────────────────────────────────────────┐       ┌──────────────────────────────────────────────┐
       │ Active Process Windows                       │       │ Active Process Windows                       │
       │  ┌──────────┐  ┌──────────┐                  │       │  ┌──────────┐  ┌──────────┐                  │
       │  │ Chrome   │  │ Webstorm │  [Noah App Window]│       │  │ Chrome   │  │ Webstorm │                  │
       │  │          │  │          │  ┌────────────┐  │       │  │          │  │          │                  │
       │  └──────────┘  └──────────┘  │ [Room 3D]  │  │       │  └────┬─────┘  └──────────┘                  │
       │                              │  (Noah)    │  │       │       │◀─── [Sitting on top!]                │
       │                              └────────────┘  │       │    [Noah] (Full-screen Transparent Canvas)   │
       └──────────────────────────────────────────────┘       └──────────────────────────────────────────────┘
```

### 2.1 윈도우 마우스 이벤트 동적 제어 (setIgnoreMouseEvents)
*   **외출 즉시**: Electron 메인 프로세스는 앱 창의 크기를 모니터 주 디스플레이 전체 화면(`mainWindow.setBounds(screen.getPrimaryDisplay().bounds)`)으로 확대하고 투명화 지점을 확장합니다.
*   **마우스 무시 해제 기준(Raycast Detection)**: 
    *   전체 화면 창이 마우스 클릭을 막으면 사용자의 실업무 사용이 불가능해집니다. 따라서 기본 동작은 `mainWindow.setIgnoreMouseEvents(true, { forward: true })` 상태(클릭 투과 패스스루)를 유지합니다.
    *   **포인터 무비 감지**: 렌더러가 마우스 포인터 좌표를 분석하다가, 노아의 아바타 3D 히트박스크 바운더리 내부로 마우스가 올라섰을 때(Raycast hit)만 즉각 IPC를 통해 `setIgnoreMouseEvents(false)`로 스위칭합니다.
    *   이를 통해 사용자는 Noah 캐릭터 자체만 정확히 드래그해 올리거나 만질 수 있고, 캐릭터가 없는 빈 데스크탑 영역은 아무 부작용 없이 뒤편의 다른 앱들을 눌러 사용할 수 있습니다.

### 2.2 룸 투명도 스위칭 (Room Alpha Transition)
*   노아가 방 전면 방향(카메라 방향)으로 우아하게 걸어 나와 문을 나서는 순간, 방의 root 3D 그룹인 `Room.group` 내 모든 매티리얼의 `.opacity` 값을 0으로 crossfade 페이드아웃 보간 처리하여 부드럽게 소멸시킵니다.
*   자연스러운 데스크탑 정착을 위해 바닥 평면에 투명 섀도우 리시버 평면(`Shadow Material`)만 남겨두어, 사용자의 작업표시줄(Taskbar)이나 열려있는 앱 위로 노아의 소프트 섀도우가 은근하게 투사되도록 물리 실재감을 유지합니다.

## 3. 실시간 OS 활성 윈도우 감지 및 물리학 (Active Window Physics)

노아가 단순 바탕화면 평면 바닥뿐만 아니라, **사용자가 활성화하여 포커싱하고 있는 외부 프로그램 창들을 딛고 걷게 만드는 것**이 이 기믹의 핵심 가치입니다.

### 3.1 활성 윈도우 정보 수집 (Active Window Bounds Reader)
메인 프로세스는 주기적으로 플랫폼 사양에 맞춘 네이티브 C++/쉘 쿼리를 전송하여 현재 포커스된 외부 윈도우들의 스크린 좌표 경계값([Bounds]{x, y, width, height})을 가져옵니다.

*   **Linux**: `xdotool getactivewindow getwindowgeometry` 명령어 사용 또는 `node-window-manager` 라이브러리 연동
*   **Windows**: `GetForegroundWindow` 및 `GetWindowRect` Win32 API 활용
*   **macOS**: Native AppleScript 컴파일 또는 `CGWindowListCopyWindowInfo` 접근

수집된 활성 윈도우 바운딩 박스 정보 데이터(`{ left, right, top, bottom }`)는 IPC `system:metrics:window` 핸들러를 거쳐 실시간으로 3D 렌더러단으로 주입됩니다.

### 3.2 3D 씬 내 가상 콜라이더 투영 (Invisible Box Colliders)
*   렌더러는 주입받은 외부 윈도우의 스크린 픽셀 좌표 바운딩 박스를 **Three.js 3D 월드의 평면 좌표계로 3차원 투영 및 리사이징(Project/Unproject)**합니다.
*   투영된 위치에 투명색의 얇고 단단한 가상의 가이드 컬라이더 상자(`THREE.Box3` 또는 투명 `Mesh`)들을 동적으로 생성하고 움직입니다.

```
       [사용자 실제 Chrome 브라우저]                     [Three.js 3D 가상 공간 매핑]
  ┌───────────────────────────────────┐               ┌───────────────────────────────────┐  y = window_top
  │ Chrome Window [Top Bar]           │               │ ░░ Invisible Collider Box ░░░░░░  │  (노아가 딛고 설 표면)
  ├───────────────────────────────────┤  ========▶    ├───────────────────────────────────┤
  │                                   │               │                                   │
  │ Render Content                    │               │                                   │  y = window_bottom
  └───────────────────────────────────┘               └───────────────────────────────────┘
                                                     x = window_left                     x = window_right
```

### 3.3 노아의 데스크탑 물리학 기믹
생성된 보이지 않는 윈도우 콜라이더들을 기반으로, 노아의 캐릭터는 다음과 같은 운동학 규칙을 수행합니다:

1.  **지붕 위 도보 (Roof Walking)**:
    외부 활성창의 `Top Bar (상단 바 기붕 x, y)` 표면이 Noah 캐릭터의 실시간 발끝 중력 Raycast 범위에 잡히면, 노아는 바닥이 아닌 활성창의 지붕을 물리 바닥면으로 정식 인지하여 그 위를 아장아장 걸어 다닙니다.
2.  **모서리 경계 정지 및 앉기 (Edge Detection & Sitting)**:
    상단 지붕 끝 도메인(윈도우 모서리)에 도달하면 추락하지 않게 스스로 발걸음을 멈춥니다. 그 뒤, 윈도우 모서리에 발을 늘어뜨리고 걸터앉아(`sit_edge` 애니메이션) 사용자의 업무 지점을 구경하는 귀여운 기믹을 전개합니다.
3.  **윈도우 추락과 미끄러짐 (Falling & Sliding)**:
    사용자가 활성 앱 창을 마크해 마우스로 드래그하여 화면 저 멀리 빠르게 이동시켜 버리면, 아래 지지 기반 콜라이더가 사라지면서 중력 물리 법칙에 의해 노아의 캐릭터는 "악!" 하고 비명을 지르며 바탕 화면 바닥 높이까지 아래로 뚝 낙하(`falling` → `land` 또는 주저앉는 `dizzy` 애니메이션)합니다.
4.  **창문 노크 및 장난 (Knocking & Peeking)**:
    사용자가 노아가 서 있던 창을 다른 창 앞으로 덮어 활성을 해제해 버리면, 노아는 덮여 가려진 윈도우를 다시 보려 앞으로 찾아와 화면 유리에 가볍게 노크를 하며 "내 디딤돌 돌려줘!" 하고 투덜대는 전용 소셜 대사(`dialog`)를 투척합니다.

## 4. 로드맵 및 단계별 목표 연동 지침

이 시스템은 고난도 OS 네이티브 제어 기술과 Three.js 정밀 프로젝션이 요구됩니다. 바이브 코딩으로 꼬이는 것을 완전히 예방하기 위해 아래와 같이 단계별로 끊어 정제 개발 마일스톤에 반영합니다.

*   **스텝 1 (바탕화면 이탈 및 투명화 보정)**: Stage 13 개발 시 Electron 전체 화면 투명 레이어로의 자연스러운 프레임 리사이즈 및 레이캐스터 기반 `setIgnoreMouseEvents` 핸들링 확립.
*   **스텝 2 (네이티브 윈도우 좌표 획득)**: 메인 프로세스에 플랫폼별 윈도우 Bounds 가져오기 쉘 파서 탑재 및 렌더러 전달 IPC 구현.
*   **스텝 3 (콜라이더 투영 및 중력 강하)**: 렌더러에서 스크린 좌표 픽셀을 3D Three.js Bounds 박스로 전사 투영하는 unprojection 수식 교정 및 중력 Raycast 낙하 연동 구현.
*   **스텝 4 (아바타 모서리 감지 및 전용 가구 걸터앉기 애니메이션 통합)**: Stage 14 자산 완성 시점에서의 `sitting_edge` 애니메이션 클립 리타겟팅 및 인지 기믹 최종 튠업.
